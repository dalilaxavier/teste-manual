# Plano de Testes

## 1. Identificação do Projeto:

- Nome do Projeto: AgendaLab
- Ambiente: https://agendalabqa.vercel.app/login
- Data de Elaboração: 19/08/2026
- Responsável: Dalila Xavier


## 2. Objetivo

- Avaliar se as funcionalidades do sistema atendem aos requisitos especificados, identificando defeitos, inconsistências e comportamentos inesperados que possam comprometer a qualidade do produto.


## 3. Escopo

**Dentro do Escopo:**

- Autenticação de Usuários.
- Dashboard.
- Catálogo de Serviços.
- Novo agendamento.
- Listagem de Meus Agendamentos.
- Filtros de Agendamentos.
- Cancelamento de Agendamento.
- Reagendamento.
- Navegação e Layout.
- Reset de Dados de Teste.
- Persistência de Dados.
- Validação de Disponibilidade de Horário.
- Acessibilidade e Responsividade.


**Fora do Escopo:**

- Página de Requisitos do Sistema.


## 4. Técnicas de Teste

- Particionamento de Equivalência - utilizado para identificar classes de entradas válidas e inválidas. 
- Análise de Valor Limite - utilizada para validar limites das regras de negócio.
- Transição de Estado - utilizada para validar mudanças de estado dos agendamentos.
- Teste Baseado na Experiência - utilizado para explorar o sistema, buscando identificar comportamentos inesperados e inconsistências. 


## 5. Tipos de Teste

- Testes Funcionais.
- Testes de Usabilidade.
- Testes de Acessibilidade.
- Testes de Responsividade.


## 6. Critério de Entrada

- Análise de requisitos concluída.
- Ambiente de teste disponível.
- Dados de teste necessários disponíveis.
- Cenários de teste definidos.


## 7. Critério de Saída

- Todos os casos de teste planejados executados.
- Defeitos identificados registrados e classificados.
- Relatório de Testes finalizado.


## 8. Ambiente

- Sistema operacional: Windows 10.
- Navegador: Google Chrome - Versão: 151.0.7922.110.


## 9. Ferramentas

- VS Code - organização das anotações e documentações. 
- Snipping tool - captura de tela e gravação de evidências. 
- Git/GitHub - versionamento e armazenamento de documentação.
- DevTools - testes de responsividade.


## 10. Riscos

- Alterações no ambiente podem impactar a execução dos testes.
- Diferenças de comportamento entre desktop e mobile podem impactar diretamente os testes de responsividade.
- Comportamentos não especificados podem dificultar a definição do resultado esperado.
